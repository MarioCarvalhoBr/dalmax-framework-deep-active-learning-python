# ADR 0008: One campaign manifest drives a single, deduplicated re-execution of all three papers

- **Status:** Accepted
- **Date:** 2026-09-29

## Context

The three-paper plan (`.specs/experiments/papers-roadmap.md`) needs many runs that, spelled out
per paper, overlap: RNHAL "full" appears in paper 3's §6.1, §6.2 (reference row) and §6.3 tables
and in the cross-paper comparison; TexHAL "full" the same in paper 2 (and in paper 3's
comparison); `RandomSampling` @ n_query=100 is the baseline of all three papers; the
"w/o representation module" row (ImageNet ResNet-50 features + hierarchical k-means) is identical
for papers 2 and 3 and is also paper 1's KMH baseline. The previous execution was split across
environments (paper-1 benchmark on the lab machine, ablations on Colab T4), so tables of
different papers mixed numbers from different hardware. The user asked (2026-09-29) for one clean
re-execution on a Colab Pro A100, same seeds {1,2,3}, same protocol, with **no redundant runs**:
every distinct configuration runs exactly once and every table that needs it points to that run.

## Decision

We will keep a single source of truth, `files_config/campaign/manifest.json` (generated by
`scripts/campaign/build_manifest.py`, mirrored by `manifest_micro.json` for CPU smoke), listing
**run groups** (one distinct computation = params JSON + strategy + n_query + n_init_labeled +
n_round, swept over the seeds), **aliases** (differently-spelled configs that are the same
computation as a canonical group) and the **tables** of each paper (rows -> run ids). `used_by`
on each group is derived from the tables. `dalmax/campaign.py` validates it, expands it to
`(run, seed)` jobs and runs them (`python -m dalmax.campaign {list,run,verify}`);
`dalmax/reporting/campaign_report.py` reads the same tables, resolving aliased rows to the one
canonical run.

Redundancy is enforced by code, not convention: `effective_signature` reduces a run to the
computation it performs (resolved config minus bookkeeping such as `dir_results`; presets resolved
like `build_strategy` does), `validate_manifest` rejects two groups with the same signature (no
exceptions) and rejects an alias whose signature differs from its canonical group. Ownership rule:
a group consumed by **more than one paper lives under `shared/`** (`shared/random_nq100`,
`shared/kmh_nq100`, `shared/texhal_full`), every other group under its own paper; `used_by` lists all
consumers and the paper-specific ids (e.g. `p1/KMH/nq100`) are aliases of the shared group. Execution order: paper 1 at n_query=100 first, then rnhal, texhal, paper 1 at 50 and 10,
then the upper bound.

## Consequences

- 192 runs instead of the naive per-paper total; every shared number is identical in every table
  by construction (one run), and a reviewer can audit the dedup by reading one JSON.
- Adding a row/paper table is a manifest change (edit the builder, regenerate), and
  `tests/test_campaign.py` fails if the committed manifests drift from the builder.
- Papers 2/3 comparison tables depend on paper-1 runs (KMH@100, RandomSampling@100) -- the parts are
  not independent; split sessions must still run `paper1` before reporting.
- The already-executed trees (`results/ablations/`, `results/dalmax{1,2}/`) stay untouched
  (append-only); the campaign writes a new root, `results/campaign_a100/`.
- Related: ADR 0007 (per-method ablation layout, still valid for the ablation-only scripts) and
  ADR 0009 (single shared "no representation" run).
