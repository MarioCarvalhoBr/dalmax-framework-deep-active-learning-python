# ADR 0010: `tools/` for CLIs, the campaign as the only run path, and hardware-agnostic repository

- **Status:** Accepted
- **Date:** 2026-09-29

## Context

After ADR 0008/0009 the campaign manifest became the single source of truth for what runs, yet the
repository still carried three generations of run tooling next to it: the per-GPU reference-benchmark
scripts (`scripts/benchmark/`), the per-GPU ablation scripts with their `METHOD`/`SKIP_EXISTING`
plumbing (`scripts/ablations/`, `scripts/colab/run_ablations_colab.sh`), and the matching Makefile
targets, reporter (`dalmax/reporting/ablation_report.py`) and migration tool
(`results_doctor`). Four CLIs (`trainer.py`, `predict.py`, `loader.py`, `gui.py`) also sat at the repo
root, mixed with docs and config. Separately, the campaign had been named after one specific GPU
(results directory, spec file and manifest name carried the GPU model; runbook steps said to select that model), and GPU model names
had leaked into code comments, tests, notebook metadata and specs, even though `run_metadata.json`
already records the real GPU at runtime (`dalmax/experiment/environment.py`). The code review of the
campaign (verdict APPROVE) also left follow-ups: determinism was reported as a bare boolean, resume
trusted `results.json` alone, and the seed audit was silent on a missing log.

## Decision

1. **`tools/` holds the CLI entry points.** `trainer.py`, `predict.py`, `loader.py`, `gui.py` moved
   there with `git mv` (history kept); `tools/_bootstrap.py` puts the repo root on `sys.path` so
   `python tools/<x>.py` works from any working directory; `tools/README.md` documents them.
   `dalmax.campaign` launches `tools/trainer.py`. `scripts/` keeps non-CLI helpers only
   (`make_micro_dataset.py`, `campaign/build_manifest.py`, `colab/setup_colab.sh`).
2. **The campaign is the only way to run and report.** Deleted: `scripts/benchmark/*`,
   `scripts/ablations/*`, `scripts/colab/run_ablations_colab.sh`, the `ablations-*`/`ablation-report*`/
   `benchmark-*`/`smoke-ablations`/`ablations-colab` Makefile targets, `ablation_report.py`,
   `results_doctor.py` (+ its notebook and tests). The one piece other code depends on, the leaf
   completeness check, survives as `dalmax/reporting/leaf_check.py`. The per-method configs under
   `files_config/ablations/{rnhal,texhal}/` stay because the manifest references them. Nothing under
   `results/` or `docs/results/` was touched: the executed 2026-08-26 RNHAL batch and its committed
   tables remain as history. Runbooks and the Colab notebook describe the campaign flow only.
3. **The repository is hardware-agnostic.** No GPU model name appears in code, configs, scripts,
   Makefile, tests, notebooks, runbooks, README/CLAUDE/AGENTS, `.claude/` or `.specs/` (except
   past-tense execution-history records). The campaign is `campaign` (`results/campaign/`,
   `docs/results/campaign/`, `.specs/experiments/campaign.md`, manifest `name`/`results_root`
   regenerated by `build_manifest.py`). The GPU is identified only by each run's
   `run_metadata.json` `environment.gpus[*].name`, captured at runtime; docs use `<gpu-name>` and tell
   the operator to check `environment.gpus[0].name` in the first run. Tests use a fake GPU name.
   `tests/test_hardware_agnostic.py` enforces it; the rule lives in `.claude/rules/reproducibility.md`.
4. **Review follow-ups.** (a) Determinism is honest: `torch.use_deterministic_algorithms(True,
   warn_only=True)` is recorded as the string `"warn_only"`, ops that had no deterministic kernel are
   captured (`dalmax.seeding.record_nondeterministic_ops`) into `determinism.nondeterministic_op_warnings`,
   and `fill_uninitialized_memory` is disabled; docs say GPU determinism is best-effort. (b) A job is
   done only if its leaf holds the full artifact set (`campaign.job_done` uses `check_leaf`), and the
   reporter writes `results.json` last. (c) The seed audit reports WARN for a missing/unreadable log
   and `campaign verify` exits 0 (ok) / 1 (incomplete job or FAIL) / 2 (only WARN). (d) `campaign`
   accepts `--exclude-strategy A,B` (list/run/verify); `make campaign-smoke` excludes the two
   adversarial baselines by default (far too slow on CPU; `SMOKE_EXCLUDE=` includes them); the full
   manifest keeps them for the GPU campaign. (e) Nits: `BrokenPipeError` handled in the campaign CLI,
   `FullSupervised` documents that `n_query` is ignored, KMH at n_query 10/50 lives under
   `paper1/nq{N}/` like the other paper-1 strategies, confusion-matrix titles state the real number of
   runs averaged, and the runbook warns about ~18 GB of checkpoints for 192 runs.

## Consequences

- One way to run, verify and report; less code and fewer stale docs. Anyone needing a single ablation
  config runs `make campaign-run PART=rnhal` (or `texhal`).
- The legacy tree `results/ablations/` can no longer be re-verified or re-reported with in-repo
  tooling; its committed tables and specs remain the record. Re-creating that tooling would need a
  new decision.
- Run directories of the campaign changed name (`results/campaign/`); nothing had been run under the
  old GPU-specific name.
- GPU determinism claims in papers must be limited to seed-averaged results; the metadata shows which
  runs touched non-deterministic ops.
- Follow-up: still outstanding is a lab-machine smoke of the `tools/` layout and the first real GPU
  execution of the campaign (wall-clock TBD).
