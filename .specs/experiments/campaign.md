# The campaign (2026-09-29)

One clean re-execution of **everything the three papers need**, on one execution environment
(any GPU machine: Colab Pro or the lab machine; the GPU is recorded per run in `run_metadata.json`), same seeds `{1,2,3}`, same protocol, **no redundant run**: every
distinct configuration runs exactly once and every table of every paper points to that single run.
Decision record: ADR 0008 (manifest + dedup) and ADR 0009 (shared "w/o representation" run).
Single source of truth: `files_config/campaign/manifest.json` (generated by
`scripts/campaign/build_manifest.py`; micro mirror `manifest_micro.json`); engine
`dalmax/campaign.py`; reports `dalmax/reporting/campaign_report.py`.

## Protocol (unchanged from the thesis paper-1 chapter)

`n_init_labeled = 100`, `n_round = 8`, `n_epoch = 10`, batch 256, lr 0.05, momentum 0.3
(`files_config/campaign/params_paper1.json` = the DANINHAS block of
`files_config/benchmark/params_df_gpu_0.json`), hierarchy `[600,200,100]` / `sample_sizes [30,15,2]`,
SSRAE `q=13`, VCTex `q=(5,17)`. Fixed test set; the pool is the 8,086 training images. There is
**no validation split** in this project's protocol (pool/test only, as in the thesis) and none is
invented here, including for the upper bound.

## Commands

```bash
make campaign-list                        # job table + counts per part
make campaign-run PART=all                # everything, skip-existing (re-run = resume)
make campaign-run PART=paper1|upper_bound|rnhal|texhal|texhal_q17   # or comma-separated
make campaign-verify                      # OK/INCOMPLETE/MISSING per job + seed-consistency audit
make campaign-report                      # docs/results/campaign/ (tables md/tex/csv, confusion matrices)
make campaign-smoke                       # micro campaign on CPU (seed 1) -> results/smoke_campaign/;
                                          # skips AdversarialBIM/AdversarialDeepFool (64 of 70 jobs)
```

`python -m dalmax.campaign {list,run,verify} --part ... [--micro] [--seeds 1] [--exclude-strategy A,B]
[--dry-run] [--no-skip-existing] [--device cuda]`. **Exclusion** (`--exclude-strategy`, 2026-09-29): a comma list of strategy names dropped from
`list`/`run`/`verify` and the seed audit (unknown names fail fast); the manifest itself is not
changed, so the GPU campaign still runs them. `make campaign-smoke` (and `MICRO=1` targets) pass
`AdversarialBIM,AdversarialDeepFool` by default because they are far too slow on CPU
(`SMOKE_EXCLUDE=` includes them); with the same exclusion `verify` does not report them MISSING.
Execution order (independent of `--part`): paper 1 at nq100
first (the shared canonical runs land early), then rnhal, texhal, texhal_q17, then paper 1 at nq50 and nq10,
then the upper bound -- what is missing if a budget runs out is the least reusable part. Papers 2/3
comparison tables need paper 1's `shared/*` runs and `shared/texhal_full`: run those parts before
reporting.

## Seeds and determinism

`seed_everything` seeds Python/NumPy/PyTorch, sets cudnn deterministic (benchmark off),
`CUBLAS_WORKSPACE_CONFIG=:4096:8`, `torch.use_deterministic_algorithms(True, warn_only=True)` and
`torch.utils.deterministic.fill_uninitialized_memory = False`; `run_metadata.json` records a
`determinism` block (seed, `deterministic_algorithms: "warn_only"`, cudnn flags, cuBLAS config,
`fill_uninitialized_memory`, `nondeterministic_op_warnings` = the ops torch warned had no deterministic
kernel during that run). Guarantees: identical seeds give identical initial labeled sets, selection
randomness and data order; bit-identical metrics on CPU (golden tests); **GPU determinism is
best-effort only** (`warn_only`), so GPU results may differ run to run and across GPU models/drivers --
report seed-averaged numbers. `campaign verify` runs the **seed-consistency audit**: for each seed,
the `Initial labeled idxs (sorted)` line of every run's `log-dalmax.log` (all strategies/configs;
`FullSupervised` excluded) must be identical -- PASS/FAIL per seed with the offenders listed, and
**WARN** when a run's log is missing/unreadable (nothing to compare). `verify` exit code: 0 all jobs OK
and audit PASS; 1 an incomplete/missing job or a FAIL/NO_DATA audit; 2 only WARNs.
**Resume**: a job counts as done only if its leaf holds the full artifact set
(`dalmax/reporting/leaf_check.py`); the reporter writes `results.json` last, so a run killed
mid-report is re-run, not skipped.

## Wall-clock

The paper-1 `AdversarialBIM`/`AdversarialDeepFool` baselines use the original per-sample DeepAL semantics (one sample at a time; KI-38). BIM is capped at 50 iterations and samples that cannot reach the decision boundary (saturated float32 prediction, zero gradient) get distance `inf` and are never queried before converged ones; DeepFool has a matching zero-gradient guard (KI-39, found on the real campaign 2026-09-30) and are the slowest groups; they are excluded from `make campaign-smoke` by default.

Measured by the real execution: the whole campaign (192 runs) spanned 2026-09-30T00:23Z to
2026-10-05T15:04Z of wall-clock across several Colab sessions with resume (see the execution record
below). Per-run durations are not aggregated here (TBD; derivable from each run's `run_metadata.json`
start timestamp and `log-dalmax.log`). The earlier Colab ablation batch took about 9-10 min per
ablation-config run. Micro CPU smoke: ~18-40 s per micro run.

**Findings recorded (2026-11-01)**: (1) RNHAL-full at the reference hierarchy (0.8805) beats every
paper-1 method at nq100 and the deeper `L=4 [800,600,200,100]` hierarchy is the best RNHAL row
(0.8955), 2.0 points below the upper bound (0.9157). (2) TexHAL with Q=[5,17] (0.8259) is *below* its
own single-Q rows (Q=17: 0.8745) and below the best paper-1 method; this drove KI-40 / ADR 0011
(**superseded by the 2026-11-02 findings below**: the canonical configuration is now Q=17).
(3) The 2026-08-26 RNHAL batch (Colab, see `ablation-study.md`) reported 0.8949 for the same
`stage_full` config; the campaign gives 0.8805. The difference (0.0144, roughly 1.7 std of the
campaign seeds) is consistent with GPU and code-version variance and was not investigated further;
the campaign numbers are the authoritative ones.

**Findings recorded (2026-11-02, after part `texhal_q17`)**: (1) With Q=17 both TexHAL stage ablations
now tell a clean story: removing either module hurts, and the representation module matters most
(weighted F1: full 0.8745; w/o hierarchical 0.8454, -2.9 points; w/o representation 0.8224, -5.2 points).
Under Q=[5,17] the ablation was not informative: w/o hierarchical (0.8190) was only 0.7 points
below full (0.8259) and its macro F1 (0.7735) was above full (0.7687). (2) The reference hierarchy is no longer the best TexHAL row:
`L=3 [300,100,50]` is (0.8842 / 0.8398), +1.0 point weighted over the reference, within one std
(0.0201). (3) TexHAL (Q=17) now edges the best paper-1 method at nq100 (0.8745 vs LeastConfidence 0.8716,
+0.3 points weighted, well within std) and stays below RNHAL (0.8805, -0.6 points). The Q=[5,17]
history tables remain in the report as `6_2_q5_17`/`6_3_q5_17`.

**Implementation findings (2026-11-02, while writing paper 1; KI-41, KI-42)**: the ResNet-50 model has no
dropout layer, so `LeastConfidenceDropout`, `MarginSamplingDropout`, `EntropySamplingDropout` and
`BALDDropout` do not perform MC-dropout (KI-41), and `KMeansSampling`/`KCenterGreedy` cluster an untrained
random 50-d projection (KI-42). The `paper1` tables are reported as executed, with this disclosure. **Author decision (2026-11-02): accepted as-is**: the runs are kept, the behaviour is disclosed in paper 1, and the fix (6 strategies x 3 budgets x 3 seeds = 54 runs as a new part) is deferred to a future campaign; no re-run.

**Round-0 finding (2026-11-02, KI-43)**: round-0 metrics of the same seed differ across run groups although the initial labeled sets are identical: KMH differs from all others because `resnet50()` construction consumes the torch RNG before round-0 training, and the rest tracks the Colab runtime image of each session (best-effort GPU determinism), so round-0 points and cross-image comparisons must not be read as method effects.
